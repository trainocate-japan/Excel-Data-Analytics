■ 講師用メモ：重回帰分析の想定解

回帰用のデータ整形は受講者が行う。想定される設計と結果は次のとおり。

目的変数 解決所要時間（受付→解決の時間数）。右に大きく歪むため LN(1+時間) の対数変換を推奨 対象行 解決日時が空欄の516件を除外して7,484行 説明変数A（受付時点） 優先度レベル／影響度レベル／緊急度レベル／受付時刻／休日フラグ／営業時間外フラグ／電話受付フラグ 説明変数B（対応過程） 再割当回数／再オープン回数／更新回数／関与グループ数／ナレッジ利用／問題管理紐付け／変更要求紐付け／ベンダー関与

想定される結果 Aのみ：決定係数 R2 ≒ 0.02　／　A+B：R2 ≒ 0.48（目的変数は対数、本ファイル作成時にPythonで算出） 論点① 受付時点の情報だけでは解決時間はほとんど説明できない。優先度で所要時間が読めるという通念が否定される 論点② R2を押し上げるのは更新回数・関与グループ数など「対応した結果」の変数。

受付時点では取得できないため予測には使えない。R2が高い＝良いモデルではない

論点③ 優先度は 影響度×緊急度 でほぼ機械的に決まる（優先度レベル ≒ 影響度+緊急度-2）。

3つ同時に投入するとVIFが優先度13.9・緊急度5.9・影響度5.0となり係数が不安定になる

論点④ 観察データなので因果ではない。「関与グループ数が多いと遅い」は

「たらい回しをやめれば速くなる」の証明にはならない（難案件だからまたいだ、が同じくらい成り立つ）

Excelでの実行 ［ファイル］→［オプション］→［アドイン］→［分析ツール］を有効化 →［データ］→［データ分析］→［回帰分析］ 変数の上限 分析ツールの回帰は説明変数16個まで、かつ連続した範囲。カテゴリのダミー変数を足す場合は変数を絞る判断が必要

■ 軽量版について

全24,918件から8,000件をランダム抽出した研修用の軽量版です（乱数シード42）。 主要な発見は全件版と一致します（SLA達成率63.0% / Critical未達成率100% / 解決時間中央値21.7時間 / ナレッジ利用あり・なしの未達成率74.8%・30.5% / 重回帰の決定係数 受付時点のみ0.020・全変数0.475）。

マスタについて M_コードマスタは全件版のまま。抽出により出現しないコードが含まれます。

実務のマスタも未使用コードを持つため、そのままにしてあります。

件数の変化 カテゴリ57→48種、担当グループ69→65種、再オープン発生275→82件。

少数区分の議論をさせたい場合は、この点に注意してください。

■ テーブル化について

各データシートはExcelテーブルに変換済みです。テーブル名は次のとおり。

T_インシデント テーブル名「インシデント」 T_作業履歴 テーブル名「作業履歴」 M_コードマスタ テーブル名「コードマスタ」

構造化参照が使えるため、範囲が実データに自動で収まります。全列参照（A:A）による 不要な重さが起きにくく、行を追加しても範囲を直す必要がありません。

書き方の例 VLOOKUP("カテゴリ_"&[@カテゴリID], コードマスタ, 4, FALSE)

COUNTIFS(作業履歴[インシデント番号], [@インシデント番号])　※先頭に = を付けて使用

演習にする場合 テーブルを解除して配布すると、Ctrl+T によるテーブル化そのものを演習にできます。

［テーブルデザイン］→［範囲に変換］で解除できます。
